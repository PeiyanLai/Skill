# Flow Explorer（通用可编辑交互流程文档）

把**任意领域**的流程生成为可交互、可在页面内直接编辑的自包含 HTML 文档。产出是单个 `.html` 文件，任何人用浏览器打开即可查看和编辑——不需要服务器、不需要安装依赖、不需要设计工具权限。

## 目录结构与定位

```
flow-explorer/
├── SKILL.md                          ← 本文件：工作流程与规范
├── assets/
│   └── template.html                 ← 通用编辑器模板（引擎完整可运行，含演示数据）
├── references/
│   └── html-template-notes.md        ← 设计系统 token 与引擎实现契约（深度定制才需要读）
└── examples/
    └── 对讲机组队-flow.html           ← 真实案例：从模板填充数据生成
```

**核心思路：编辑器引擎是现成的，做一张新流程图 = 复制模板 + 替换数据区。** 不要从零手写 HTML。

## 产出物

一个 HTML 文件，包含：

1. **Mermaid 流程图** —— 占满全屏宽度，可缩放、可平移、节点可点击；图由数据模型驱动，编辑后即时重渲染
2. **在线编辑能力** —— 双击节点改文字、**按住方框任意拖动**（连线与阶段容器实时跟随）、新增节点、删除节点、增删改连线、撤销/重做
3. **卡片视图** —— 节点按阶段分组展示，与流程图数据联动
4. **详情面板（悬浮抽屉）** —— 默认隐藏、流程图占满全宽；点击节点从右侧滑出，查看「目的」与「处理逻辑」或切换到编辑表单，×/Esc/点空白处收起
5. **连线管理视图** —— 以列表方式管理全部连线（起点/终点/标签/线型）
6. **一键下载高清图片** —— 「⬇ 下载图片」按当前布局（含手动拖动、改过的文字）导出 3 倍分辨率 PNG，自带标题与图例，纯色底
7. **导入/导出** —— 导出 Mermaid 源码与 JSON 数据；**导入 JSON** 可加载队友分享的流程数据，团队协作闭环
8. **图例栏 + 缩放控件 + 快捷键** —— +/−/0/F 键、滚轮缩放、拖拽平移、Ctrl+Z 撤销

## 何时使用

| 场景 | 是否使用 |
|------|---------|
| 可视化一个产品功能的交互流程（任何功能） | ✅ |
| 可视化前后端系统的执行链路、服务间调用 | ✅ |
| 端到端记录一条 AI Agent 管线 | ✅ |
| 审批流、状态机、多角色协作流程 | ✅ |
| 产出团队可点击、可当场修改的需求评审材料 | ✅ |
| 把一张流程截图/一段描述变成可维护的文档 | ✅ |
| 只需要一张静态流程图图片 | ❌ 直接输出 Mermaid 代码或截图即可 |

## 工作流程

### 第 1 步：理解流程（任意领域）

收集信息。以下任一形式都可以作为输入：

- **自然语言描述** —— 用户在对话中说明需求或流程
- **需求/设计文档** —— 用户提供 PRD、方案文档，从中提取流程
- **已有 Mermaid 代码** —— 用户粘贴或指向包含 mermaid 的文件
- **截图** —— 用户提供流程图截图
- **代码** —— 用户指向源码，从执行路径提取流程

需要弄清楚：
- 有几个主要阶段/场景？
- 关键决策点（分支）在哪里？
- 哪些步骤并行、哪些串行？有没有异常/降级路径？
- 节点可以分成哪些类别？

### 第 2 步：定义节点分类（使用 NIO 色板）

确定 4–7 个分类为流程着色。**分类颜色必须取自 NIOFlow 设计系统色板**，不得自造颜色。模板内置 7 个通用槽位，按领域改 label（或增删）即可：

| 槽位 key | 边框 / 填充 | 语义 | 不同领域下的 label 示例 |
|----------|------------|------|--------------------------|
| `core` | `#00bebe` / `#D0F5F5` | 核心对象/主流程（**主色，每图仅一类**） | 组队共享 · 订单主链路 · Agent 调度 |
| `infra` | `#004b64` / `#DEF0F4` | 硬件、底层能力、基础设施 | 硬件对讲 · 存储层 · 模型推理 |
| `process` | `#3D8090` / `#E1EEF1` | 常规处理、次级链路 | 在线链路 · 服务处理 · 数据清洗 |
| `account` | `#5D4DD4` / `#ECE9FB` | 账号、绑定、第三方身份 | 账号绑定 · 授权登录 · 三方对接 |
| `external` | `#D49922` / `#FBF1DA` | 商城、交易、外部动作 | 购买流转 · 支付 · 消息推送 |
| `decision` | `#00AAAA` / 白底虚线菱形 | 决策/分支节点 | 是否有网 · 是否通过校验 · 路由判断 |
| `alert` | `#D14545` / `#FBE9E9` | 异常/降级（**慎用，能不用就不用**） | 失败提示 · 降级链路 |

### 第 3 步：结构化节点（仅中文）

为每个节点定义：

```
id:      唯一短标识，大写（如 "PTT"、"NET_CHECK"）
title:   节点显示名（中文，尽量 ≤ 14 字）
tag:     分类 key
purpose: 一句话说明「目的」（中文）
logic:   多行说明「处理逻辑」（中文，可用 ①②③ 列步骤）
```

将节点分组到阶段（phase）。每个阶段有：编号（`num`，可以是「阶段 1」也可以是「场景 A」「泳道·风控」等）、标题、一句话提示（hint）、节点 id 列表。

### 第 4 步：设计连线

连线规则（保证自动布局稳定）：
- 主流程用实线 `style: 'solid'`，条件/可选/降级路径用虚线 `style: 'dotted'`，分支出口写 `label`
- **禁止回边**（后面的节点连回前面的节点会破坏布局）——改为在节点「处理逻辑」中标注「↩ 回到 X」
- 决策节点用 `decision` 分类（自动渲染为菱形）

### 第 5 步：填充模板生成 HTML（不要从零写）

1. 复制 `assets/template.html`，改名为 `{项目名}-flow.html`
2. 找到文件中 `/* ==== FLOW-EXPLORER:DATA:START ==== */` 到 `/* ==== FLOW-EXPLORER:DATA:END ==== */` 的数据区，**只替换这一段**，共三部分：
   - **① `CONFIG`** —— 标题、副标题、`docId`（本地存档标识，**每个文档必须唯一**，否则不同文档在浏览器里互相覆盖存档）、导出文件名前缀、页脚
   - **② `TAGS`** —— 分类色板：改 label、增删分类（颜色仅限第 2 步的色板）
   - **③ `INITIAL`** —— 流程数据：`nodes` / `edges` / `phases`，`layout` 留空 `{}`
3. 数据区之外是通用编辑器引擎，**一律不要改动**；需要调整视觉或交互行为时，先读 `references/html-template-notes.md` 里的实现契约

模板自带一个 5 节点演示流程，直接打开即可预览引擎效果；演示数据同时是数据结构的活文档。

### 第 6 步：浏览器 QA

用无头浏览器打开文件验证，修完问题再交付：

- Mermaid 渲染为 SVG（而非原始文本），无 JS console 报错
- CONFIG 的标题/副标题/页脚注入页面
- 缩放控件可用（+/−/fit/reset）
- 单击节点 → 悬浮面板滑出详情；双击 → 编辑表单；×/Esc/点空白 → 收起
- 按住节点拖动 → 节点跟手移动、连线与阶段容器实时跟随；松手后拖动可被撤销
- 修改标题保存 → 图中文字更新；新增/删除节点 → 图和卡片视图同步更新
- 连线管理中增删连线 → 图即时更新
- **拖动节点 + 改文字后点「下载图片」→ 下载的 PNG 反映调整后的最终布局与新文字**（这是该功能的核心契约）；图片为纯色底、含标题与图例、无网格
- 导出 JSON → 修改 → 导入，数据正确回灌
- 刷新页面 → localStorage 恢复编辑结果（含拖动位置）；重置恢复初始版本；「自动布局」清除全部手动位置

## 编辑能力（模板引擎已内置）

| 交互 | 行为 |
|------|------|
| 单击节点 | 悬浮面板滑出，显示目的/处理逻辑，附「编辑」「删除」按钮 |
| 双击节点 | 直接进入编辑表单（焦点在标题输入框），改文字保存后图即更新 |
| 拖动节点 | 按住方框拖到任意位置，连线与阶段容器实时跟随；偏移存入 `state.layout` 随存档持久化；「自动布局」一键恢复自动排版 |
| 新增节点 | 工具栏「+ 新增节点」→ 表单填写，可顺手选上游/下游节点自动连线 |
| 删除节点 | 面板中删除（`confirm()` 确认），级联删除相关连线与位置偏移 |
| 编辑连线 | 「连线管理」视图表格化增删改（起点/终点/标签/实虚线） |
| 撤销/重做 | 快照历史栈；一次完整拖动记一条历史；Ctrl+Z / Ctrl+Shift+Z |
| 自动保存 | 每次修改写入 `localStorage`（key 由 `CONFIG.docId` 决定）；「重置」恢复初始版本 |
| **下载图片** | 「⬇ 下载图片」把**当前屏幕上的最终布局**导出为高清 PNG（3 倍分辨率、纯色底、含标题与图例）。先随意拖动排版、改文字，满意后再导出 |
| 导出 | 「导出 Mermaid」下载 `.mmd`；「导出 JSON」下载完整数据模型（含 layout） |
| 导入 | 「导入 JSON」加载队友导出的 JSON，整体替换当前数据（可撤销） |

## 数据区技术约束

引擎的 `sanitizeLabel()` 会在渲染时自动清洗节点文字（`"` `#` `<` `>` `|` 等危险字符、超长自动折行），但写数据时仍需遵守：

- 节点标题尽量 ≤ 14 字；多行放到 `logic` 里，不要塞进 title
- **节点标签中禁止 emoji**——部分渲染环境会崩
- **禁止回边**——用「↩ 回到 X」文字标注代替
- `logic` 多行用 `\n`（JS 字符串转义），详情面板按 `pre-wrap` 展示
- JS 字符串里的中文弯引号（「」''）安全；ASCII 直引号需转义
- 改完数据后必须语法检查：提取 `<script>` 内容跑 `node --check`

## 视觉设计：NIOFlow 设计系统（强制）

模板已内置全部视觉规范；替换数据不会破坏它。若需定制，完整 token 与页面结构契约见 `references/html-template-notes.md`。要点：

- 品牌主色 NIO Teal：`#00bebe`（强调/激活态）、`#00D4D4`（高亮/hover）、`#D0F5F5`（浅色块）、`#004b64`（深色底）
- 默认渐变 `linear-gradient(135deg, #00D4D4, #00bebe)`；**只允许青绿渐变与冷调灰度渐变**，禁止暖色/彩虹渐变
- 主色仅用于强调：单块面积 ≤15%，每屏 ≤3 处主色实例
- 中性色一律用青调灰（ink-1 `#1A1F1F` / ink-2 `#2E3D3D` / ink-3 `#5C7070` / ink-4 `#8AABAB`），**禁止纯灰 `#888`/`#666`、禁止纯黑阴影**
- 背景仅限 `#FFFFFF` / `#F0FAFA` / `#E8FAFA`；分割线 `#D8EEEE` / `#B8DEDE`
- 头部为深青渐变横幅（`#00323F → #004b64 → #007D8C`）+ 青色 radial 辉光装饰
- Mermaid 视口为**纯色底板**（`--canvas`，默认 `#FFFFFF`），不加网格、不加任何底纹线条——导出的图片同色，屏幕与图片观感一致；缩放控件绝对定位在视口左上角（右侧留给悬浮抽屉，避免遮挡）
- 详情面板为右侧**悬浮抽屉**（约 460px，绝对定位盖在内容上）：默认收起、流程图始终占满全宽
- `alert` 红 `#D14545` 仅用于异常/降级语义节点与「重置」按钮

不要即兴发挥颜色和布局，设计系统就是契约。

## 输出规范

- **文件格式**：单个 `.html` 文件（从 `assets/template.html` 复制填充）
- **命名**：`{项目名}-flow.html` 或用户指定
- **`docId` 唯一**：不同文档必须使用不同 `CONFIG.docId`，否则浏览器本地存档互相覆盖
- **位置**：当前工作目录或用户指定路径
- **依赖**：无（唯一外部资源是 CDN 加载的 `mermaid.min.js`；用户离线场景可把它内联进文件）
