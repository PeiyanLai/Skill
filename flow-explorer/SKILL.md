# Flow Explorer（可编辑交互流程文档）

生成可交互、可在页面内直接编辑的自包含 HTML 流程文档。产出是单个 `.html` 文件，任何人用浏览器打开即可查看和编辑——不需要服务器、不需要安装依赖、不需要设计工具权限。

## 产出物

一个 HTML 文件，包含：

1. **Mermaid 流程图** —— 可缩放、可平移、节点可点击；图由数据模型驱动，编辑后即时重渲染
2. **在线编辑能力** —— 双击节点改文字、新增节点、删除节点、增删改连线、撤销/重做、导出
3. **卡片视图** —— 节点按阶段分组展示，与流程图数据联动
4. **详情面板** —— 点击任意节点查看「目的」与「处理逻辑」，并可切换到编辑表单
5. **连线管理视图** —— 以列表方式管理全部连线（起点/终点/标签/线型）
6. **图例栏 + 缩放控件 + 快捷键** —— +/−/0/F 键、滚轮缩放、拖拽平移、Ctrl+Z 撤销

## 何时使用

| 场景 | 是否使用 |
|------|---------|
| 端到端记录一条 AI Agent 管线 | ✅ |
| 可视化后端系统的执行流程 | ✅ |
| 产出团队可点击、可当场修改的需求评审材料 | ✅ |
| 把一张流程截图/一段描述变成可维护的文档 | ✅ |
| 只需要一张静态流程图图片 | ❌ 直接输出 Mermaid 代码或截图即可 |

## 工作流程

### 第 1 步：理解流程

收集系统信息。以下任一形式都可以作为输入：

- **自然语言描述** —— 用户在对话中说明流程
- **已有 Mermaid 代码** —— 用户粘贴或指向包含 mermaid 的 `.md` 文件
- **截图** —— 用户提供流程图截图
- **代码/文档** —— 用户指向源码或文档，从中提取流程

需要弄清楚：
- 有几个主要阶段/步骤？
- 关键决策点（分支）在哪里？
- 哪些步骤并行、哪些串行？
- 节点可以分成哪些类别？

### 第 2 步：定义节点分类（使用 NIO 色板）

确定 4–7 个分类为流程着色。**分类颜色必须取自 NIOFlow 设计系统色板**（详见 `references/html-template-notes.md`），不得自造颜色。可用的分类配色：

| 色系 | 边框色 | 浅色填充 | 典型用途 |
|------|--------|----------|----------|
| 主色青 | `#00bebe` | `#D0F5F5` | 核心对象/主流程（每图仅一类使用主色） |
| 深青 sage | `#004b64` | `#DEF0F4` | 底层能力、硬件、基础设施 |
| 灰青 slate | `#3D8090` | `#E1EEF1` | 常规处理、次级链路 |
| 紫 | `#5D4DD4` | `#ECE9FB` | 账号、绑定、第三方 |
| 琥珀 | `#D49922` | `#FBF1DA` | 商城、交易、外部动作 |
| 判断（描边菱形） | `#00AAAA` | `#FFFFFF` | 决策/分支节点，虚线描边 |
| 红 `#D14545` | 仅限告警/失败类节点，能不用就不用 | | |

### 第 3 步：结构化节点（仅中文）

为每个节点定义：

```
id:      唯一短标识，大写（如 "PTT"、"NET_CHECK"）
title:   节点显示名（中文，尽量 ≤ 14 字）
tag:     分类 key
phase:   所属阶段 id
purpose: 一句话说明「目的」（中文）
logic:   多行说明「处理逻辑」（中文，可用 ①②③ 列步骤）
```

将节点分组到阶段（phase）。每个阶段有：编号、标题、一句话提示（hint）、节点 id 列表。

### 第 4 步：设计数据模型与连线

**整个页面由一个 JSON 数据模型驱动，Mermaid 源码是从模型生成的，不是手写死的。** 这是支持编辑的关键。

```js
const state = {
  nodes:  { ID: {title, tag, phase, purpose, logic}, ... },
  edges:  [ {from, to, label, style: 'solid'|'dotted'}, ... ],
  phases: [ {id, num, title, hint, nodes: [ID, ...]}, ... ],
};
```

连线规则（保证 dagre 布局稳定）：
- 使用 `flowchart TD`（自上而下）
- 每个阶段一个 `subgraph`，节点声明写在 subgraph 内、**全部连线写在所有 subgraph 之后**
- **禁止回边**（后面的节点连回前面的节点会破坏布局）——改为在节点文字中标注「↩ 回到 X」
- 主流程用实线 `-->`，条件/可选路径用虚线 `-. 标签 .->`
- 决策节点用菱形 `{"文字"}`，其余用矩形 `["文字"]`

### 第 5 步：实现编辑器（核心）

生成的 HTML 必须实现以下编辑能力，实现方式为「**改数据模型 → 重新生成 Mermaid 源码 → mermaid.render 重渲染 → 重新绑定事件**」，布局始终由 Mermaid 自动计算，稳定可靠：

| 交互 | 行为 |
|------|------|
| 单击节点 | 右侧面板显示该节点的目的/处理逻辑，附「编辑」「删除」按钮 |
| **双击节点** | 直接进入编辑表单（焦点在标题输入框），改文字保存后图即更新 |
| 新增节点 | 工具栏「+ 新增节点」→ 表单填写标题/分类/阶段/描述，可顺手选择上游、下游节点自动连线 |
| 删除节点 | 面板中删除，需 `confirm()` 确认，级联删除相关连线 |
| 编辑连线 | 「连线管理」视图：表格列出全部连线，起点/终点用下拉选择，可改标签、切换实/虚线、删除、新增 |
| 撤销/重做 | 每次修改前把 `state` 快照压入历史栈；Ctrl+Z / Ctrl+Shift+Z（或 Ctrl+Y），工具栏也有按钮 |
| 自动保存 | 每次修改写入 `localStorage`（key 带文档标识）；提供「重置」按钮恢复初始版本 |
| 导出 | 「导出 Mermaid」下载 `.mmd` 源码；「导出 JSON」下载数据模型，便于回灌 |

关键实现要点：

- `mermaid.initialize({ startOnLoad: false, securityLevel: 'loose', theme: 'base', themeVariables: {…NIO 色板…} })`
- 用 `await mermaid.render('graph-' + n, src)` 编程式渲染（每次用递增 id），把返回的 `svg` 注入容器
- **不要用 mermaid 的 `click` 语句绑定事件**。渲染完成后查询 `svg` 中的 `.node` 元素，其 id 形如 `flowchart-<节点ID>-<序号>`，用正则 `/^flowchart-(.+?)-\d+$/` 提取节点 ID，自行 `addEventListener` 绑定 click / dblclick——这样重渲染后重新绑定即可，且不依赖全局函数
- 重渲染时**保留当前缩放/平移状态**（首次渲染才自动 fit）
- 节点文字过长时自动按每 ~12 个字符插入 `<br/>` 折行

### 第 6 步：浏览器 QA

用无头浏览器打开文件验证，修完问题再交付：

- Mermaid 渲染为 SVG（而非原始文本），无 JS console 报错
- 缩放控件可用（+/−/fit/reset）
- 单击节点 → 详情面板出现内容；双击 → 出现编辑表单
- 修改标题保存 → 图中文字更新；新增/删除节点 → 图和卡片视图同步更新
- 连线管理中增删连线 → 图即时更新
- 刷新页面 → localStorage 恢复编辑结果；重置按钮恢复初始版本

## 技术约束

### Mermaid 语法陷阱（重要）

- `A & B --> C` 多边简写在 Mermaid 10 CDN 版**不支持**——逐行分开写
- **禁用 `==>` 粗箭头**——与标签语法组合会解析报错，统一用 `-->`
- **节点文字中禁止字面 `\n`**——多行用 `<br/>`
- **节点文字中禁止 `#`**——Mermaid 会当作 HEX 颜色前缀，用「＃」或「No.」替代
- **节点标签中禁止 emoji**——部分渲染环境会崩
- 禁止回边（`A --> B` 之后又 `B --> A`）——布局会乱
- 节点文字中的 `"` 替换为 `'`，`&` 转义为 `&amp;`，`<`/`>` 替换为全角 `＜`/`＞`（编辑器的 `sanitizeLabel()` 必须做这层清洗，因为文字是用户随时输入的）
- 虚线带标签用 `A -. 标签 .-> B`；实线带标签用 `A -->|标签| B`
- subgraph 标题格式：`subgraph P1["&nbsp;阶段 1 · 名称&nbsp;"]`，内部声明 `direction TB`
- 所有连线统一写在全部 subgraph 之后（节点归属由声明位置决定，连线位置不影响归属）

### JS 字符串安全

- 中文弯引号（""）在 JS 字符串里安全；ASCII 直引号 `"` 在 `"` 字符串里会断——用模板字符串或转义
- 交付前必须语法检查：提取 `<script>` 内容跑 `node --check`

### SVG 尺寸

- `.mermaid-stage svg { max-width: none !important; width: auto !important; height: auto !important; }`

### 详情面板

保持简单——两个区块，同样式：

- **🎯 目的**（h3, 15px, 700）
- **⚙️ 处理逻辑**（h3, 15px, 700）

正文统一 `.content` 样式（13px、`--ink-2`、line-height 1.8、`white-space: pre-wrap`）。不加彩色底、不加边框盒子。

## 视觉设计：NIOFlow 设计系统（强制）

**所有输出必须使用蔚来 NIOFlow 设计系统**，完整 token 与页面结构规范见 `references/html-template-notes.md`。要点：

- 品牌主色 NIO Teal：`#00bebe`（强调/激活态）、`#00D4D4`（高亮/hover）、`#D0F5F5`（浅色块）、`#004b64`（深色底）
- 默认渐变 `linear-gradient(135deg, #00D4D4, #00bebe)`；**只允许青绿渐变与冷调灰度渐变**，禁止暖色/彩虹渐变
- 主色仅用于强调：单块面积 ≤15%，每屏 ≤3 处主色实例
- 中性色一律用青调灰（ink-1 `#1A1F1F` / ink-2 `#2E3D3D` / ink-3 `#5C7070` / ink-4 `#8AABAB`），**禁止纯灰 `#888`/`#666`、禁止纯黑阴影**
- 背景仅限 `#FFFFFF` / `#F0FAFA` / `#E8FAFA`；分割线 `#D8EEEE` / `#B8DEDE`
- 阴影用青色冷调，如 `0 16px 34px -22px rgba(0,60,70,0.15)`
- 头部为深青渐变横幅（`#00323F → #004b64 → #007D8C`）+ 青色 radial 辉光装饰
- Mermaid 视口带 24px 网格底纹，缩放控件绝对定位在视口右上角
- 详情面板固定在右侧（约 500px），左缘 2px 青绿渐变饰条
- 卡片：白底、`#D8EEEE` 细边、青调阴影、hover 时底部出现渐变条；阶段编号为渐变胶囊

不要即兴发挥颜色和布局，设计系统就是契约。

- **依赖**：无（唯一外部资源是 CDN 加载的 `mermaid.min.js`；用户离线场景可把它内联进文件）
