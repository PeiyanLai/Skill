# flow-diagram · 交互式流程文档生成

把任何流程性内容变成**可拖拽、可编辑、可筛选**的单文件交互 HTML——零外部依赖，可发 Artifact、可嵌 WebView、可直接静态托管，人人打开浏览器就能看和改。

## 产出物功能清单（成品自带）

- **画布视图**：全屏铺满；分区虚线框自动贴合成员节点；节点单击＝编辑表单（标题/副标题/描述/维度/依赖/分区/样式），拖拽＝移动（连线实时跟随）；连线点击可改标签/反转/删除；「从此节点连线」建新边
- **卡片视图**：按阶段分组的渐变编号卡片墙，含完整描述，点卡片同样进入编辑——适合评审时逐段过
- 工具条：双维筛选（联动淡出）、＋新增节点、导出 JSON、**导出高清 PNG**、恢复默认、缩放、重置布局、视图切换
- 修改自动存 localStorage（按 KEY 隔离）；「导出 JSON」可回收任何人的编辑并入默认
- **确认终版后一键出图**：点击「导出高清 PNG」会按当前画布状态生成 3 倍分辨率图片，保留最新节点文案、位置、分区、连线和筛选淡出效果；导出时自动移除临时选中态和编辑面板，可直接插入文档或评审材料。导出器必须以当前数据和 DOM 尺寸重画**纯原生 SVG**后转 PNG，禁止使用 HTML / SVG `foreignObject` 截图，确保用户用本地 `file://` 打开时也能导出。
- 亮/暗双主题跟随系统

## 输入：接受任何形态

- **自然语言 / 需求文档**——对话或上传文件里抽流程
- **已有 Mermaid**——用户粘贴或指向含 mermaid 的 .md
- **截图 / 设计稿**——读图抽结构
- **代码 / 技术文档**——从源码提炼执行流

信息不足时先澄清：有几个大阶段？关键分支/决策点在哪？哪些步骤并行哪些串行？节点该按什么维度分类上色？

## 建模：三个可自定义维度

模板的三维筛选是**通用槽位**，按题材重命名，不要生搬硬套：

| 槽位 | 产品流程示例 | 系统/Agent 管线示例 |
|---|---|---|
| 维度一（4 个色槽 `owner/mate/frnd/team`） | 用户类型 | 模块类别（NLP/检索/生成/输出…取 ≤4 归并） |
| 维度二（`SCENS` 筛选 + 场景标签） | 使用场景 | 执行路径/分支 |
| 分区（`ZONES` 画布分组） | 叙事阶段 | 管线阶段 |
| `deps` 标签 | 依赖端/系统 | 依赖服务/模型/存储 |

色槽固定四个（青/紫/琥珀/深青），只改显示名不新增色——色彩语义一致性比数量重要。节点 8–16 个：`{id, z, x, y, u, scen, deps, t, s, d, kind?, wide?}`；痛点 `kind:"pain"`，边界说明 `kind:"note"`。描述 `d` 尽量引用原文表述；需要双语时在 `d` 里中文在前、英文换行在后。**关键数字约束（上限/距离/容量）必须保留在节点文案里**——评审时最常被追问。

边：`{f, t, l?, bend?:"left"}`。跨分区的关键跳转必须有标签；`bend:"left"` 用于会穿节点的长回流边。

## 填模板

复制 `assets/template.html`，**只改**：页面文案（`<title>`/`h1`/`.eyebrow`/`.stats`）、脚本顶部常量（`USERS`/`SCENS`/`ZONES`/`ZNAMES`/`ZMAP` 新项目置 `{}`/`KEY` **必须项目唯一**/`DEFAULT` 数据）、工具条筛选按钮文案。保留 `exportImageBtn` 与 `exportHighResPng()`；它们负责在用户完成文字与布局调整后，下载 3 倍分辨率的最终 PNG。初始坐标不必精确（分区自动贴合）：列 `x = 56 + 256*i`，行参考 `y = 118/252/330/536`，默认画布控制在 1360×680 内一屏放下。

## 生成策略（强制，防止任务中断）

按下面顺序一次完成，不能把任一步替换为「生成 SVG」「截图预览」或「另起炉灶写页面」：

1. 先复制 `assets/template.html` 到最终文件名；文件必须先落盘。
2. 只替换上一节列出的文案和数据常量，保留模板其余引擎代码不动。
3. 运行本 skill 的轻量校验；失败就修复该 HTML 并重新校验。
4. 校验通过后，把**同一个 HTML 文件**作为聊天附件/Artifact 返回。

生成过程不得依赖 npm 安装、Playwright/Chromium、远程 CDN、截图服务或浏览器自动化；这些能力缺失时仍必须继续产出 HTML。若平台没有内嵌预览，只返回可下载的 HTML 文件，不要改交 SVG 或 PNG。

## 配色：NIO 品牌默认

模板内置 NIOFlow（Ace）tokens，完整规范见 `references/nio-colors.md`。核心规则：主色 #00bebe 只做强调（选中/激活/高亮连线，单块面积 ≤15%）；中性灰用青调（禁纯灰）；暗色 #0a0a0a 底 + #00D4D4 高亮。换品牌只改四个 token 块的变量值，组件样式一律经 token 引用。

## 校验（必做，但不依赖浏览器）

```bash
node scripts/validate.mjs <生成的.html>
```

该校验只检查 HTML 结构、数据区、原生 PNG 导出器与内嵌 JS 语法，**不需要 Playwright、Chromium 或网络**。有浏览器时再手动确认节点拖拽、卡片视图和「导出高清 PNG」即可；浏览器不可用不能阻断 HTML 文件的生成和交付。

## 交付

先把最终 HTML 写入文件并运行上述轻量校验；再使用当前平台**已经提供**的文件附件/Artifact 能力返回同一个 HTML 文件。不要因为平台没有 Artifact、浏览器或截图工具而中止生成。严禁把「正在生成」的进度消息当作交付；只有校验通过并附上 HTML 后才算完成。提醒用户：页面编辑存在各自浏览器本地，要设为默认需「导出 JSON」发回合并。

## Mermaid 版（可选）

用户要"能贴进文档/GitHub/飞书"的版本、或提供 Mermaid 想美化时：flowchart（subgraph 对应分区、classDef 对应维度色）+ 交互类流程补 sequenceDiagram + 附可复制源码。**语法坑很多，动手前必读 `references/mermaid-guide.md`**（禁用语法清单、时序图分图模式、避免反向边等），完整范例见 `references/mermaid-example.md`。交付前必须本地渲染验证（npm i mermaid + 无头浏览器），语法错误会导致整图空白。
